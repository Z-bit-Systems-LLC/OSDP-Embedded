OSDP-Embedded 1.0.0 is the first stable release: a freestanding C11
implementation of SIA OSDP v2.2.2 for access control readers and controllers,
with a `no_std` Rust wrapper.

This is the first release since 0.1.0 went to crates.io in May to secure the
name. The 147 commits in between turned a working decoder into a complete
peripheral device, so the jump straight to 1.0.0 reflects that the public API is
now something we're prepared to keep stable.

## Highlights

**The PD answers every v2.2 command an ACU can legally send** outside the
deferred credential set. That includes the protocol mechanics an application
used to have to write itself:

- Status providers for `osdp_LSTAT` / `ISTAT` / `OSTAT` / `RSTAT` — the library
  owns the reply layout, your application owns the values, and every member is
  independently optional.
- A caller-owned poll-response queue for `osdp_RAW` / `KEYPAD` / `FMT` /
  `MFGREP`, emptied on a comms loss per spec 7.11/7.12 so a card read from
  before an outage is never delivered late.
- `osdp_COMSET` handled end to end, including the spec-6.13 requirement that the
  address change take effect only *after* the reply is sent, with hooks to veto
  the request and to drain the UART before retuning the baud.
- PD-side file transfer in two modes over one callback: reassembly into a
  caller-owned buffer, or streaming fragment-by-fragment with no size ceiling
  for MCUs writing straight to flash.
- Multi-part message transport (spec 5.10) carrying fragmented `osdp_MFG`.
- `osdp_ABORT`, `osdp_ACURXSIZE`, and `osdp_KEEPACTIVE`.

**A command handler's return value now maps onto the spec's Table 47 NAK
codes.** Previously anything other than success was dropped silently and the ACU
spent a full reply timeout learning nothing.

**No internal ceilings.** Working buffers are sized by one build-overridable
constant per role and can be rebound at run time to caller-owned storage with
`osdp_pd_set_buffers()`. The Secure Channel path lost the 256-byte stack scratch
that used to cap every SC message regardless of the capacity actually bound.

**Reader output tracking.** The PD and ACU decode `osdp_LED` and `osdp_BUZ` into
a resolved display state — flash phase, temporary-override countdown, and
permanent colour folded together — and call back only when what the reader is
actually showing changes. Drive your GPIO from that instead of reimplementing
the spec's timing rules.

**Rust crate parity.** The wrapper now reaches the whole PD surface: status
providers, the event queue, multi-part `osdp_MFG`, the capability checker, and
the `ABORT` / `ACURXSIZE` / `KEEPACTIVE` hooks, plus typed codecs for the full
v2.2 message set. Cargo features `pd` and `acu` gate the C compilation as well
as the Rust modules, so a PD-only firmware build genuinely carries no ACU code.

## Interop hardening

Every one of these came out of running against a real controller rather than
reading the spec harder:

- A stalled receive is aborted on the spec 5.8 inter-character timeout instead
  of leaving the decoder holding a partial frame, sized to tolerate transports
  that batch their RX.
- A short transport write is resumed rather than silently truncating the frame.
- A bad-CRC or bad-checksum command addressed to this PD is answered `NAK 0x01`
  instead of dropped, so the ACU retransmits immediately.
- Clear-text commands are refused `NAK 0x06` once secure operation is expected,
  per the spec's prohibition on interleaving unsecured packets into a secure
  session.
- `0x7F` is treated as the configuration address, with replies going out at
  `0xFF` per spec 5.9 Note 2.
- Malformed `osdp_KEYSET` NAKs `0x09` rather than `0x03`, and never overwrites
  the stored key.

## Tooling

`osdp-pd-mock` and `osdp-acu-mock` run a real PD or ACU on a serial port, closing
the interop loop in both directions. `osdp-parser` decodes OSDPCAP captures.
`osdp-mcp` exposes a virtual PD over the Model Context Protocol so an AI agent
can drive it against a controller under test — scripting replies, injecting
faults, and reading back the decoded wire history — with an optional browser view
of the reader's LEDs, buzzer, and keypad that also lets you tap a card or press a
key by hand.

## What 1.0.0 commits us to

Standard SemVer, with the public C headers and everything the Rust crate
re-exports treated as the contract. Note that **adding a member to a public
struct counts as breaking**, because consumers embed types like `osdp_pd_t` by
value in static storage. Build-time constants you're invited to override
(`OSDP_PD_BUF_LEN` and friends) are knobs, not API. The full statement is in
[docs/PUBLISHING.md](https://github.com/Z-bit-Systems-LLC/OSDP-Embedded/blob/main/docs/PUBLISHING.md).

## Not included

The credential domain — biometrics, PIV data exchange, `osdp_GENAUTH` /
`osdp_CRAUTH`, and transparent smartcard mode — is not implemented. Those all
ride the multi-part transport that already exists, so the remaining work is the
messages themselves. Also outstanding: ACU-side file transfer, auto-poll
scheduling on the ACU, and multi-record messages.

The ACU state machine is complete and drives the loopback integration suite and
`osdp-acu-mock`, but the PD is the more heavily exercised half of this release.

## Installing

```toml
osdp-embedded = "1.0"                                                    # both roles
osdp-embedded = { version = "1.0", default-features = false, features = ["pd"] }  # PD only
```

For C, add the repository as a CMake subdirectory and link `osdp::core`,
`osdp::messages`, and `osdp::pd` (or `osdp::acu`).
